# شجرة العائلة — Family Tree

تطبيق ويب لعرض شجرة العائلة بالعربية: مخطط تفاعلي (الذكور مربعات زرقاء، الإناث
دوائر وردية)، وبطاقة تفاصيل لكل شخص عند الضغط عليه، وإمكانية إضافة وتعديل وحذف
الأفراد. البيانات تُحفظ في المتصفح.

An Arabic, right-to-left family-tree SPA. Click any node to open a detail sheet
with the person's lineage, branch, parents, spouses and children; add, edit and
delete people; search and filter by branch; export to JSON/PNG or print.

## Running it

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # production bundle in dist/
npm test           # unit tests (layout, store, search)
npm run typecheck
```

Requires Node 20.19+ or 22+ (Vite 8). On older Node the build fails with
`node:util does not provide an export named 'styleText'`.

`npm run smoke` drives a real browser through the main flow and writes
screenshots to `smoke-shots/` — run `npm run build && npm run preview -- --port 4319`
first.

## On iPhone

Run `npm run serve:lan` on the laptop (builds, then serves `dist/` on
`0.0.0.0:4319`), find the machine's LAN address with `ipconfig`, and open
`http://<lan-ip>:4319/` in **Safari** on a phone on the same Wi-Fi. Tap
**Share → Add to Home Screen** and it installs with its own icon, launching
full-screen with no browser chrome. Chrome on iOS cannot install; only Safari.

Add to Home Screen itself does not need HTTPS — iOS reads the
`apple-mobile-web-app-*` meta tags and `apple-touch-icon` over plain HTTP. What
does need a secure origin is the **service worker**: over `http://` iOS does not
expose `navigator.serviceWorker` at all, so the installed app fetches from the
laptop every launch and shows a network error when the laptop is off or its IP
has changed. The tree data itself lives in the phone's own `localStorage`, so it
survives regardless.

For offline launches, serve over HTTPS instead — any static host works
(`dist/` is plain files), or on a tailnet:
`tailscale serve --bg --https=443 http://127.0.0.1:4319` (undo with
`tailscale serve --https=443 off`). `vite.config.ts` allows `.ts.net` hosts
through Vite's host check for exactly this. On a secure origin the worker
precaches the whole build — see the `precache-sw` plugin in `vite.config.ts`,
which bakes the hashed asset list into `public/sw.js` at build time.

Icons are generated by `npm run icons` into `public/`.

Touch specifics: pinch/drag pans and zooms the tree canvas (d3-zoom, with
`touch-action: none` so the page itself never zooms), the person sheet is a
bottom sheet on phones, secondary toolbar actions fold into the ⋯ menu, and
layouts respect the notch/home-indicator safe areas.

## Where the data lives

Everything is stored in your browser under `localStorage["family-tree/v1"]` —
there is no server and nothing leaves the device. **Use “تصدير JSON” to take a
backup before clearing site data or switching browsers**; “استيراد JSON” restores
it. On first run the app seeds a small example tree; “استعادة البيانات الأولية”
returns to it and discards your edits.

## How it is put together

| Path | Role |
|---|---|
| `src/model/types.ts` | `Person` / `TreeDoc`. Parent links are the source of truth. |
| `src/model/select.ts` | Children are **derived** from parent links, never stored. |
| `src/model/validate.ts` | No self-parent, no lineage cycle, gender-consistent parent slots. |
| `src/store/treeStore.ts` | Zustand store persisted to localStorage; keeps spouse links symmetric. |
| `src/tree/layout.ts` | Pure geometry: d3 tidy tree, mirrored for RTL, orthogonal connectors. |
| `src/components/` | `TreeView` (SVG + pan/zoom), `PersonDetail`, `PersonForm`, `Header`, `Modal`. |
| `src/i18n/ar.ts` | Every user-facing string, so a second locale stays possible. |

Stack: React 19 + TypeScript + Vite, Tailwind CSS v4, Zustand, d3-hierarchy /
d3-zoom, Radix Dialog, Vitest.
